Lab 01 — Reading Data

Vectors, types, missing values, data frames, and describing one variable

Overview

This lab is your first contact with R. You are not expected to have written a line of it before today.

The work is deliberately unglamorous. Before you can find anything interesting in a playtest you have to be able to load the data, look at it, and describe it without making a fool of yourself. That is what this sheet trains.

Everything here uses base R — the functions that ship with the language. You will meet the tidyverse in Lab 02. Learning base R first means you will understand what the tidyverse is doing for you rather than treating it as magic.

Function What it does
c() Builds a vector from individual values
length(), class() How many, and what type
read_csv() Reads a CSV file into a data frame
str(), head(), nrow(), names() Look at a data frame without printing all of it
$, [ , ] Pull out a column, or a slice of rows and columns
mean(), median(), sd(), range() Describe a numeric variable
quantile(), IQR() Describe the spread and the tails
table() Count a categorical variable
hist(), boxplot() See the shape of a variable

Learning outcomes

By the end of this lab you can:

  • create and index vectors, and explain what NA does to a calculation
  • load a CSV into a data frame and inspect it without printing 120 rows
  • classify any column as nominal, ordinal, discrete or continuous
  • describe a numeric variable with an appropriate measure of centre and spread
  • state, in one sentence, when the mean is the wrong summary and why

Ground rules

  • Keep the CSV files in the data/ folder of the project.
  • Type the code. Do not copy and paste from the solutions until you have tried.
  • Open the solution after your attempt, even when your attempt worked. The solution sometimes does it a better way.
  • Every exercise ends with a short written answer. Write it. The writing is the part that gets assessed later, not the code.
  • If a line of code fails, read the error before doing anything else. Most R errors name the exact problem.

Part A — Values, vectors and missing data

Exercise 01 — Build a vector and look at it [Do]

Create a vector called deaths holding the death counts from six playtest sessions: 4, 2, 7, 3, 0, 5.

Exercise 03 — A missing value poisons the arithmetic [Do]

A seventh tester’s death count was not recorded. Add NA to the end of deaths and take the mean. Then take it again so that the result is a number.

TipSolution 
deaths <- c(deaths, NA)

mean(deaths)
[1] NA
mean(deaths, na.rm = TRUE)
[1] 3.5

NA is not zero and it is not “empty”. It means unknown, and the mean of a set containing an unknown value is itself unknown. R tells you that rather than quietly guessing.

Write 2 sentences: na.rm = TRUE makes the error message go away. Explain why that is not the same thing as fixing the problem.

Exercise 04 — Filter a vector with a condition [Apply]

Using the seven-value deaths vector, produce a TRUE/FALSE vector showing which sessions had more than 3 deaths, use it to extract those death counts, then count how many sessions that is.

TipSolution 
deaths > 3
[1]  TRUE FALSE  TRUE FALSE FALSE  TRUE    NA
deaths[deaths > 3]
[1]  4  7  5 NA
sum(deaths > 3, na.rm = TRUE)
[1] 3

Two things worth noticing. deaths[deaths > 3] keeps the NA, because R does not know whether the unknown value is above 3 or not. And sum() on a TRUE/FALSE vector counts the TRUEs, because TRUE is 1 and FALSE is 0.

Write 1–2 sentences: why is sum(x > 3) a count rather than a total?

Exercise 07 — Get at a single column [Do]

Extract the score column three different ways: with $, with [[ ]], and with [ , ]. Confirm all three give the same thing.

TipSolution 
by_dollar  <- sessions$score
by_bracket <- sessions[["score"]]
by_comma   <- sessions[, "score", drop = TRUE]

identical(by_dollar, by_bracket)
[1] TRUE
identical(by_dollar, by_comma)
[1] TRUE

drop = TRUE matters: without it, [ , ] on a tibble hands you back a one-column table rather than a plain vector, and the identical check fails.

Note the variable names. Never call a variable c — you would be shadowing c(), the function you used to build every vector in Part A.

Write 1 sentence: which of the three would you use in a script another person has to read, and why?

Exercise 08 — Classify every column [Apply]

For each of these columns, state whether it is nominal, ordinal, discrete or continuous: cohort, archetype, build, score, kills, deaths, session_minutes, quit_reason.

TipSolution
Column Type Why
cohort Ordinal Novice → Regular → Veteran has a real order
archetype Nominal Scout is not more or less than Sentinel
build Nominal Two labels, no order
score Discrete Whole points, though large enough to treat as continuous
kills Discrete A count
deaths Discrete A count
session_minutes Continuous Measured time, one decimal place
quit_reason Nominal Four labels, no order

The interesting one is cohort. R has loaded it as chr — plain text — and will sort it alphabetically as Novice, Regular, Veteran, which happens to be the right order by accident. Never rely on that.

Write 2 sentences: pick one column above and explain what would go wrong if you treated it as the wrong type.

Write 2 sentences: express the gap between mean and median as a percentage of the median, for both variables. Which one is more skewed, and does its tail run left or right?

NoteCheck your answer

Score sits 2.8% below its median. Session minutes sits 12.9% below. Both are left-skewed — the mean falls below the median because a group of short sessions drags it down — but session minutes is far more so.

Comparing the raw gaps (-41 points against -3.4 minutes) would have told you the opposite, which is why the scale of the variable always has to come into it.

Challenge — Which cohort is the game actually built for? [Decide]

You have been asked a real question by the design lead: is Tidebreak too hard for novice players?

Using only what is on this sheet, produce the evidence you would take into that conversation. There is no single correct answer. There is a defensible one and an indefensible one.

ImportantOne defensible answer 
# 1. How many people are we talking about?
table(sessions$cohort)

 Novice Regular Veteran 
     33      53      34 
# 2. Centre and spread of score, per cohort
tapply(sessions$score, sessions$cohort, summary)
$Novice
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
    773    1099    1281    1253    1393    1627 

$Regular
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
    541    1291    1467    1414    1592    1917 

$Veteran
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
    579    1592    1664    1622    1829    2019 
# 3. Deaths, which is closer to "difficulty" than score is
tapply(sessions$deaths, sessions$cohort, mean)
  Novice  Regular  Veteran 
3.242424 3.094340 2.647059 
# 4. And did they leave early?
table(sessions$cohort, sessions$quit_reason)
         
          Completed test Frustrated Lost interest Technical fault
  Novice              23          6             3               1
  Regular             27         14             8               4
  Veteran             19          5            10               0
# 5. Show the shape, not just the numbers
boxplot(score ~ cohort,
        data = sessions,
        main = "Score by player cohort",
        ylab = "Score",
        col  = "grey85")

What the evidence actually shows.

Measure Novice Regular Veteran
Mean score 1253 1414 1622
Mean deaths 3.24 3.09 2.65
Median session length (min) 27.1 24.2 24.9
Quit in frustration 18% 26% 15%

Novices do score lower, and that is the finding everyone expects. On its own it looks like a difficulty problem.

Every other measure contradicts it. Novices die at almost exactly the same rate as everyone else, they play for longer than either other cohort, and they are less likely to quit in frustration than regular players. A game that was too hard for novices would show them dying more and leaving sooner. This one does not.

So the defensible answer is: no. The score gap looks like inexperience rather than difficulty — novices are playing the game safely and slowly and scoring less for it. The genuinely odd number on that table is the frustration rate among regular players, which nobody asked about and which is the thing worth chasing next.

What would make it indefensible. Comparing three mean scores, announcing that novices are struggling, and recommending a difficulty change. The number is real and the conclusion does not follow from it.

Write 3–4 sentences, using What → Pattern → Meaning → Action:

  • What did you measure?
  • Pattern — what does the evidence show?
  • Meaning — what might that mean for the design?
  • Action — what is the one change or the one further test you would recommend?
